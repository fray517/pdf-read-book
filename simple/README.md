# Простой backend (по plan.md, этап 1.1)

## Один раз: виртуальное окружение и зависимости

```powershell
cd C:\Users\feden\pdf-book-reader\simple
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

### Если pip пишет `Read timed out` к pypi.org

Увеличьте таймаут и при необходимости повторите:

```powershell
pip install --default-timeout=120 --retries 10 -r requirements.txt
```

Либо попробуйте другую сеть (например раздача с телефона) или VPN. Зеркала PyPI иногда публикуют региональные провайдеры — URL уточняйте у них.

### `ModuleNotFoundError: No module named 'pydantic_settings'`

После этапа 1.2 в `requirements.txt` добавлены новые пакеты. Активируйте то же окружение, что и для uvicorn, и выполните:

```powershell
pip install -r requirements.txt
```

(Папка venv может называться `.venv` или `venv` — неважно, главное — один и тот же интерпретатор.)

## Запуск сервера

Из каталога **`simple`** (где лежит папка `app`):

```powershell
.\.venv\Scripts\Activate.ps1
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Откройте в браузере:

- http://127.0.0.1:8000/ — перенаправление на Swagger  
- http://127.0.0.1:8000/docs — Swagger  
- http://127.0.0.1:8000/health — ответ `{"status":"ok"}`  
- http://127.0.0.1:8000/config/status — путь хранилища и флаг «ключ OpenAI задан»  

Загрузка только через **POST** `/upload`. Если открыть в браузере **GET** `/upload`, будет **405** — так и должно быть.

Остановка: `Ctrl+C` в терминале.

## Этап 1.3 — загрузка PDF

После `pip install -r requirements.txt` (нужен пакет `python-multipart`).

1. Запустите uvicorn из каталога `simple`.
2. Откройте http://127.0.0.1:8000/docs .
3. Разверните **POST /upload** → **Try it out** → выберите `.pdf` → **Execute**.
4. В ответе будут `file_id` и `filename`. Файл на диске: `STORAGE_PATH` из `.env` (по умолчанию `./data/files`), имя `{file_id}.pdf`.

Проверка в PowerShell через **curl** (путь к PDF свой; важно имя поля **`file=`** и **`@`** перед путём):

```powershell
curl.exe -X POST "http://127.0.0.1:8000/upload" -F "file=@C:\path\to\file.pdf"
```

Неверно: `-F "C:\...\file.pdf"` без имени поля и без `@` — curl выдаст ошибку про `-F`.

Убедитесь, что **uvicorn запущен**, иначе curl не подключится.

## Этап 1.4 — текст из PDF

Нужен пакет **PyMuPDF**: `pip install -r requirements.txt`.

1. Загрузите PDF через **POST /upload**, скопируйте `file_id` из ответа.
2. Откройте **GET /text/{file_id}** в Swagger или в браузере:  
   `http://127.0.0.1:8000/text/<file_id>`  
3. В ответе: `pages` (текст по страницам), `full_text` (всё подряд), `page_count`.

Для **отсканированных** PDF без текстового слоя строки могут быть пустыми — OCR будет в этапе 3.

## Этап 2.4 — скорость и голос (UI)

На странице: слайдер **скорости** (0.8–1.2×), выпадающий список **голоса** OpenAI TTS (`alloy`, `echo`, …). Состояние дублируется в JSON-блоке для проверки; на API в этапе 2 не отправляется.

## Этап 3.1 — язык текста

Зависимость: **`langdetect`** (см. `requirements.txt`). После `pip install -r requirements.txt` доступен **`POST /detect-language`** с JSON `{"text": "..."}` — ответ `{"lang": "ru"}` (код ISO 639-1). На сервере анализируется начало текста (до ~2000 символов); слишком короткая строка вернёт 400.

На фронте: после «Показать текст» нажмите **Определить язык** (нужно ≥ 20 символов в поле текста).

## Этап 3.2 — перевод на русский

Нужны **`pip install -r requirements.txt`** (пакет `openai`) и непустой **`OPENAI_API_KEY`**, если исходный язык не русский (определяется так же, как в 3.1).

- **`POST /translate/{file_id}`** — текст снова извлекается из загруженного PDF; результат на русском сохраняется рядом как **`{file_id}_ru.txt`** в `STORAGE_PATH`.
- Параметр **`?refresh=true`** — пересчитать перевод, не брать готовый `_ru.txt`.
- Если язык уже **ru**, файл просто копирует текст (без вызова OpenAI).

На фронте после загрузки PDF: **Перевести на русский** / **Обновить перевод**.

Если в логах **`getaddrinfo failed`** или ответ **503** «Нет соединения с API OpenAI» — Windows не может достучаться до **api.openai.com** (нет сети, DNS, блокировка, VPN). Проверьте браузером доступность https://api.openai.com , при необходимости VPN/другой DNS или переменные **`HTTPS_PROXY`** / **`HTTP_PROXY`** для корпоративного прокси.

## Этап 3.3 — OCR для сканов

- **`GET /text/{file_id}?ocr=true`** — если на странице мало текста слоя PDF (порог порядка 40 символов), страница растеризуется в PNG и отправляется в **OpenAI Vision** (`gpt-4o-mini`). В JSON ответа поле **`ocr_pages`** — список номеров страниц, где сработал OCR.
- Без **`OPENAI_API_KEY`** при необходимости OCR вернётся **503**.
- По умолчанию **`ocr=false`** — как раньше, только слой текста из PDF.

На фронте: включите **«OCR для сканов»** и нажмите **Показать текст**. Учтите стоимость запросов: слабых страниц может быть много.

## Этап 3.4 — сегменты для озвучки

- **`GET /segments/{file_id}`** — разбиение текста на сегменты (абзацы по `\n\n`, затем укладка в лимит **~3500** символов на сегмент, запас под TTS).
- Параметры: **`ocr`** — как у `GET /text` (извлечение страниц); **`use_ru=true`** — сегментировать содержимое **`{file_id}_ru.txt`** (сначала выполните перевод 3.2). Если **`use_ru`**, параметр `ocr` не используется.
- Ответ: массив **`segments`** с полями **`index`**, **`page_no`** (0 для цельного `_ru.txt`), **`text`**, **`char_count`**.

На фронте: **Показать сегменты**, опции перевода и OCR, превью JSON (первые 20 сегментов).

## Этап 3.5 — озвучка (OpenAI TTS)

Нужны **`pip install -r requirements.txt`** и непустой **`OPENAI_API_KEY`**.

- **`GET /audio/{file_id}/{segment_index}`** — синтез MP3 (`tts-1`) для текста сегмента (как у **`GET /segments`**: те же **`ocr`**, **`use_ru`**). Дополнительно: **`voice`** (по умолчанию `alloy`; допустимые: `alloy`, `echo`, `fable`, `onyx`, `nova`, `shimmer`), **`speed`** (0.25–4.0).
- Файлы кэшируются под **`{STORAGE_PATH}/../audio/{file_id}/`** (рядом с каталогом загрузок PDF), имя вида **`{index}_{voice}_{speed}.mp3`** (скорость в имени с подчёркиванием вместо точки).
- Повторный запрос с теми же параметрами отдаёт уже сохранённый файл без повторного вызова API.

На фронте после **Показать сегменты** отображается JSON сегментов (превью). Голос и скорость из блока «Озвучка» передаются в `GET /audio/…`.

## Этап 3.6 — читалка на фронте

- Кнопка **«Озвучить»** выполняет цепочку: текст PDF (с учётом чекбокса OCR) → язык → при необходимости перевод → список сегментов. Параметры сегментов (`ocr` / `use_ru`) выставляются так же, как при ручном сценарии (русский исходник — из PDF; иной язык — перевод и `_ru.txt`).
- Ниже появляется **плеер**: один элемент `<audio>` на текущий сегмент, рядом **текст этого сегмента**; по окончании трека автоматически подгружается следующий сегмент и воспроизводится (если пользователь уже начал воспроизведение). Кнопки **«Назад»** / **«Вперёд»** переключают сегмент без автозапуска.
- Если сегменты уже получены кнопкой **«Показать сегменты»**, тот же плеер использует их (без повторного нажатия «Озвучить»).
